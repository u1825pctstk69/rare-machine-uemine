# 店舗運用・公開手順

## 公開前（店舗側）

1. `verification.md`全13行と実機・最新配置表を照合し、正式名称・台番号・レート・シリーズ・型式を確認。
2. P-WORLD個別URLをスマートフォンで全件開き、検索を経由しないこと、正しい型式・スペックであることを確認。確認できるまで承認待ち。
3. 画像は権利者・利用規約に基づきWeb公開可否と加工/クレジット条件を確認。現状は13枚とも未確認。許諾待ちなら画像なしの`site/`を公開候補とする。画像なしでも機種名等の掲載内容を含め店舗承認が必要。
4. iPhone Safari / Android Chromeの実機でNFC起動、3カテゴリー、全詳細、P-WORLDから戻る操作、文字サイズ拡大を確認。自動テストのChromiumエミュレーションは実機検証の代わりにはなりません。
5. 公開範囲・画像有無・掲載内容を店舗責任者が承認。画像ありで公開する場合は、許諾済み画像だけを`site/`に移して参照と表示設定を変更・再テストする別変更が必要。現状のreviewImagesモードを公開用にしない。
6. GitHubの契約でPrivateリポジトリからのPages利用が可能か確認。PrivateリポジトリでもPagesサイトが一般公開され得ます。Public変更は別途明示承認がない限り行わない。
7. 承認後、GitHub PagesのGitHub Actions配信を設定し、成果物を`site/`だけに限定。`review-assets/`、テスト、ドキュメントはアップロードしない。現段階では公開ワークフローもPages設定も未作成。
8. 公開後に発行されたHTTPSの実URLで全画面と13リンクを再確認。現在の店舗確認用注意文・リンク確認中表記は確認完了後の別変更で更新。

## 公開後のNFC設定（QRは使用しない）

1. GitHub Pagesが実際に発行したトップページのHTTPS URLを確認。仮URLやプレビューパラメーターをタグに書かない。
2. URL書き込みに対応するNDEFタグ（例：NTAG213等）と書き込みアプリを用意。
3. 「URL/URI」レコード1件としてトップURLをタグ1個に書き込む。個人情報は書き込まない。
4. iPhone/Androidでタッチ→通知→トップ→機種→台番号→P-WORLDを実機確認。iPhoneなど通知のタップが必要な端末があります。
5. 金属付近では金属対応タグ・設置位置を検討し、現場で読み取り確認。タグを「タッチでレア台を探す」のPOPと一緒に設置。
6. URL確定・動作確認後、必要に応じてタグをロック。ロックは元に戻せない場合があるため、それまではロックしない。
7. 台入替時も同じトップURLを維持し、データだけ更新。タグの差し替えを避けられます。

## 稼働向上の確認

最重要KPIは掲載台の稼働です。ページ閲覧数を最終目標にしません。導入前後の同曜日・同時間帯の台別稼働（店舗既存のアウト/ゲーム数/稼働時間等）を比較し、非掲載台・営業日数・入替・イベントの影響を合わせて評価してください。個人を識別せず店舗単位の既存集計を使います。低稼働機種の紹介文・掲載順の調整は店舗承認を経て行います。

本サイトにはアクセス解析、Cookie保存、顧客入力、DB、個人情報収集処理を追加していません。GitHub PagesやP-WORLDのサービス側のログ/規約は別途確認してください。空き状況や遊技結果を保証する表示はありません。
